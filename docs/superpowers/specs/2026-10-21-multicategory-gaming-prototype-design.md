# 多品类互动平台原型设计

日期：2026-10-21
状态：设计已获用户确认；书面规格待审阅
依据：[参考站调研与复刻蓝图](../../6686-reference-analysis.md)

## 目标

在当前工作区中新建**独立项目**，制作受参考站信息架构启发的高保真、可点击网页原型。首版让访客从统一导航进入体育、直播、真人、电竞、棋牌、彩票、老虎机、奖池及账户/记录页面，并可沿代表性的深层路径浏览。它用于评审产品结构、视觉设计与交互，不接入真实资金、下注、结算或未授权的第三方游戏/视频。

本项目保留现有 `marsket-demo` 的文件和行为，不覆盖其已有改动。原型使用原创名称、图形和示例数据；页面结构可借鉴参考站，品牌素材、直播画面、游戏资源与供应商内容不复制。

## 方案选择

选择独立 React/Vite 应用目录 `reference-platform-prototype/`，与现有项目平行。另两种方案分别是：在 `marsket-demo` 中增加一套独立路由（依赖已有应用结构，容易混淆导航和状态）和直接改造现有应用（会覆盖正在进行的工作）。用户已选择独立项目与高保真可点击流程。

## 界面结构

桌面采用顶部品牌/余额栏、可收合左侧分级导航、中央主工作区、右侧媒体/聊天或选择单的三栏体系。视觉基调为浅灰背景、白色内容面、清晰的蓝色操作强调和密集但可扫读的赛事/游戏信息。体育列表用紧凑行与赔率单元；游戏大厅用类别图标、供应商筛选和封面卡；赛事详情用比分横幅、玩法标签和分组盘口。媒体面板显示与当前页面相符的示例直播封面、播放状态及聊天空态。窄屏时左栏变抽屉、右栏变可切换底部面板，保持主要内容可用。

## 信息架构与首版交互

| 区域 | 页面与可点击路径 | 关键状态 |
| --- | --- | --- |
| 首页 / 体育 | 推荐赛事 → 运动分类 → 联赛/滚球/即将/早盘 → 赛事详情 | 搜索、筛选、收藏、比分、盘口折叠、赔率更新样式 |
| 赛事详情 / 选择单 | 玩法标签 → 赔率选择 → 单注/串场面板 | 选项列表、金额输入与快捷金额、赔率变动提示；提交仅展示演示说明 |
| 直播 | 按运动过滤赛事 → 选择直播 | 赛事列表、示例播放器、静音/全屏 UI、聊天空态 |
| 电竞 | 游戏项目 → 赛程标签 → 对阵详情 | 游戏/联赛过滤、BO 场次、胜负等示例盘口 |
| 电竞体育 | 体育下的独立入口 → 电竞足球/篮球 → 对阵详情 | 短时制赛程、实时比分、让分/大小等示例盘口 |
| 真人 | 玩法/桌台筛选 → 桌台详情 | 路单预览、桌台状态、供应商承载页示意 |
| 棋牌 / 捕鱼 | 类别/供应商/搜索 → 游戏承载页 | 同名不同供应商区分、更多游戏推荐、全屏入口 |
| 彩票 | 彩票大厅、投注记录、开奖历史、彩票规则 | 仅做明确标注的示意流程；不编造参考站未验证的彩种规则 |
| 老虎机 / 奖池 | 榜单/供应商/搜索 → 游戏详情 | RTP、波动性、奖池字段按各自含义展示；示例游戏启动占位 |
| 我的 / 记录 | 账户中心 → 体育记录或游戏记录 | 余额样本、设置展示、状态/日期筛选、空态；无真实账户数据 |

首版样本数据涵盖每个分类至少一个可见子类别和可到达详情，并包括正常、空、加载、不可用状态。页面上的金额、赔率、比分、奖池和账户资料均标注为示例，不伪装为实时或已结算数据。游戏承载页只展示原创封面、供应商元数据和“演示内容”区域；若将来接入供应商，使用独立适配接口替换该区域。

## 应用边界与数据流

- `catalog`：类别、供应商与游戏元数据，供大厅、搜索和推荐使用。
- `events`：运动、联赛、赛事、直播标识、盘口和选项，供首页、列表、详情、直播使用。
- `slip`：浏览器内暂存的选项草稿；支持添加、移除、金额输入和单注/串场切换。实际提交操作保持不可用并说明原因。
- `media`：右侧面板的页面关联状态，切换示例画面、静音与聊天空态，不请求第三方受保护视频。
- `account`：纯示例余额、设置和空记录。不会读取参考站的登录状态或凭据。

路由按用户可理解的路径组织，例如 `/sports`、`/sports/live`、`/sports/event/:id`、`/esports`、`/casino`、`/board`、`/lottery`、`/slots`、`/jackpots`、`/games/:id`、`/account`、`/records`。用 URL 承载当前品类和详情，以便刷新与直接访问；筛选项可在查询参数中保存。

## 失败、边界与验收

搜索无结果、赛事无可用盘口、游戏不可用、媒体未加载时显示清楚的页面级空态。赔率变化时保持选择单可读并提示重新确认，但不创建订单。彩票页明确标识“示意”，直到获得实际玩法资料。所有主要按钮需要有可见反馈；没有内容的入口不可做成看似可用的死按钮。

验收以浏览器逐页检查为准：九类主入口均能到达；每类至少一条深层路径能返回；体育选择单能添加/删除选项、输入金额、切换单注/串场；目录筛选与搜索能改变可见结果；窄屏导航与媒体面板可操作；直接打开深层 URL 可显示相应页面。构建通过后再做一次视觉核对，检查布局、溢出、可读性和示例数据标识。

## 后续阶段

真实赛事数据、实际赔率流、账户、钱包、游戏供应商、开奖、支付和结算分别属于后续集成阶段；其接口、授权与业务规则需独立确认。首版原型的数据层与页面层分开，以便将来逐项替换。
