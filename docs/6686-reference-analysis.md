# 6686 参考站调研与同类产品复刻蓝图

调研日期：2026-10-21。参考站：[6686ipkyamr39.app](https://6686ipkyamr39.app/)。通过已登录网页逐页观察，未提交投注、游戏下注、充值或提现。站内实时比分、赔率、奖池、数量和直播内容持续变化，下文只记录结构与交互，不以观察时的数值作为产品常量。

## 结论与范围

这个产品由三层组成：统一的站点外壳（顶部账户与钱包、左侧分类导航、右侧直播/聊天）、自营的赛事与游戏目录页面、供应商提供的嵌入式游戏/视频。体育与电竞赛事的列表、详情、盘口和投注单属于站内核心体验；真人、棋牌、捕鱼、老虎机等大量实际游戏由第三方提供。复刻应先完成信息架构、目录和可演示交互，再以明确的供应商接口接入获得授权的内容。页面上出现的品牌、视频和游戏素材不能直接当作本项目资源。

## 公共界面与视觉系统

- 桌面布局为固定蓝色顶栏 + 可收合左侧分类导航 + 中央内容区 + 右侧直播/聊天区。观察窗口约 1093×827 时，三栏宽度大致为 176 / 500 / 377 像素；这只是当前响应式断点的观测值。
- 左侧导航层级清楚：体育下有热门、足球、篮球、网球、乒乓球、电子竞技、电竞体育、羽毛球、棒球、直播；娱乐下有真人、电竞、棋牌、彩票；电子下有老虎机、奖池。当前分类用饱和蓝底与白字强调。
- 顶栏左侧为大号白色品牌字标，右侧依次为活动/功能图标、通知/客服类入口、CNY 余额及加号、头像。启动第三方游戏时余额位短暂显示“游戏中…”，说明存在游戏钱包或状态切换，但具体结算机制未验证。
- 中央区域主要使用圆角白底容器、灰白页面背景、浅灰卡片与蓝色主按钮。体育列表比游戏大厅更紧凑，赔率按钮以灰底展示，变化时会用红/绿突出；赛事详情由比分横幅、分类标签、分组盘口卡组成。
- 真人、棋牌、彩票、老虎机等目录页右栏常驻主持人/桌台视频与聊天。体育页右栏则播放所选赛事视频。聊天输入处显示需 VIP1 才能发言，空态为“暂时没有对话”。右栏内容与中央当前品类可能不同步，复刻时应定义明确的默认直播与切换策略。
- 游戏目录使用上方图标式二级分类、供应商胶囊按钮、搜索/筛选、三列游戏卡。卡片通常有方形封面、名称和供应商标识。

## 体育与电竞业务流程

1. 从体育首页、分类或直播目录进入赛事列表。列表以联赛分组，含赛程阶段、主客队、比分/计时、盘口数量、视频/收藏图标及少量核心盘口（让分/让球、大小、独赢等）。即将赛事有 3/6/12/24 小时窗口；列表可搜索和排序。
2. 点击比赛名称进入赛事详情。页首显示联赛、双方、比分、时间和局/节比分；下方以“全部、让球、总分、独赢、球队、单节、半场”等标签筛选盘口。不同运动的名称和市场不同，例如篮球有获胜者、让分、全场及半场总分、球队得分、单双；足球有让球、进球、半场和组合盘口。盘口可折叠、置顶，部分卡片展示双方支持率百分比。
3. 点击赔率只会选择选项并打开右侧投注单，不会立即下注。单注单显示所选比赛、玩法、选项、当前赔率、滚动比分、金额输入和数字键盘/快捷金额/MAX；未输入金额时提交按钮禁用。切换“串场”时仅有一个选项会显示“盘口数量不足，无法串场”。实时赔率会刷新；因此正式实现必须重新确认报价与可用状态。未验证提交、取消、派彩、赛果结算。
4. 直播目录把带视频的赛事集中展示，右侧播放器有静音、音量、画中画、全屏。直播与聊天区可被投注单占用；详情页本身仍保留赔率操作。
5. 电子竞技既出现在体育导航，也有独立电竞赛事页。电竞页有游戏项目图标横列和联赛/滚球/早盘/串场/冠军/赛果标签；电竞体育则展示短时制足球/篮球比赛。信息模型应把 `sport`、`gameTitle`、`eventPhase`、`competition`、`market` 区分开。

## 其他品类业务流程

### 真人

真人大厅的顶层分类为优选、好路、百家乐、多台、龙虎、骰宝、真人秀、轮盘；在好路页还有全部、经典、极速二级筛选、“全路”筛选和列表/卡片视图切换。列表展示百家乐路单、局数/状态和桌台画面预览。点击一个百家乐桌台进入统一的第三方游戏承载页，页面内能看到荷官视频、历史路单、筹码档位及闲/庄/和、对子、幸运类投注区域。这里只验证了画面与入口，没有下注。站内负责桌台发现和启动，游戏内规则、直播及下单由供应商提供。

### 棋牌与捕鱼

棋牌大厅的可见分组为捕鱼、麻将、扑克、牛牛、百人、其他；供应商筛选有 DB、开元、Choice、KS。游戏卡点击后进入统一承载页，保留本站顶栏/侧栏、返回、全屏和“更多游戏”。“捕鱼大师”实际加载独立第三方 Ocean Hunter 游戏画面，证明棋牌目录并非站内逐个实现的 React 游戏。捕鱼、扑克等同用一个目录与启动流程，但游戏内交互由不同供应商决定。目录存在同名游戏来自不同供应商的情况，数据主键不能只用展示名称。

### 彩票

页面可见彩票大厅、投注记录、开奖历史、彩票规则的文字入口，中央主体在多次进入后持续灰色空白。“暂无资讯”只表示当前资讯状态。不能据此推断彩种、选号界面、开奖周期、赔率或订单结构；这些需独立资料或可访问环境验证。

### 老虎机与奖池

老虎机大厅按推荐、热度、新品、赔率和最高回报组织，供应商包括 Red Tiger、PG、JDB、PT、CQ9 等，支持搜索。进入单个老虎机时，本站展示游戏名称、奖池、RTP、波动性、中奖线和玩法标签；游戏本体在嵌入区域加载，下面为“更多游戏”。“热赔率/冷赔率”列表中的百分比不应未经确认就当成理论 RTP，“最高回报”中才明确有 RTP 标识。奖池页按供应商切换，突出动态奖池总额与游戏级奖池/RTP。

### 账户、记录与个性化设置

“我的”页把个人资料、投注记录、优惠活动、卡券中心、隐私安全、钱包管理、交易明细、卡片管理、主播相关功能和帮助链接分组。顶区同时展示余额、其他权益计数以及充值、提现、VIP、红利快捷入口。游戏设置提供游戏偏好、欧洲盘赔率格式、赛事设置、现场比分、国际/亚洲页面设计和盘口展示模式；系统设置含语言、时区与浅色/深色/自动主题。上述为可见入口，未操作会改变账户或资金的设置。

“记录”入口分体育记录和游戏记录。体育记录可筛选全部、提前结算、现场、未结、已结、取消，并按今日、昨日、近 7 日、近 30 日或日期区间查看；有美东时区 GMT-04:00 开关说明。游戏记录的状态筛选为全部、未结、已结。当前账户未产生记录，因此记录卡的详细字段和实际结算展示尚未验证。

## 建议的信息与状态模型

| 对象 | 最低字段 | 关系/状态 |
| --- | --- | --- |
| Category / Provider / Game | 类别层级、供应商 ID、游戏 ID、名称、封面、标签、可用状态 | 同名不同商可共存；游戏引用供应商与分类 |
| Competition / Event | 运动或电竞游戏、联赛、双方、开赛时间、阶段、比分、直播标识 | `upcoming → inplay → settled`；直播与结果单独关联 |
| Market / Selection | 事件 ID、盘口类型/时段、让分或总分线、选项、赔率、更新时间、开放状态 | 盘口可能暂停、赔率变动、结果已结算 |
| Bet Slip | 单注/串场、选项快照、金额、预估回报、校验状态 | 选赔率后建草稿；提交前重新校验赔率、余额、串场资格 |
| Live Stream / Chat | 媒体类型、关联事件或桌台、授权来源、音量/全屏、权限 | 体育视频与主持人流共用右栏容器；聊天受等级限制 |
| Wallet / Record | 币种、余额、流水、订单、派奖、转账状态 | 与游戏供应商的余额状态需明确对账边界 |

## 复刻实施顺序

1. **产品外壳与导航**：建立独立路由和响应式三栏框架，定义样式变量、空态、加载态、顶部钱包、左侧多级导航和右侧媒体容器。先用原创标识、文案与占位素材。
2. **目录页**：体育首页/列表/直播、真人大厅、电竞赛事、棋牌、老虎机、奖池的分类筛选、搜索和游戏卡。用结构化样本数据实现可浏览状态。
3. **深层详情**：赛事详情与动态盘口、选择赔率后的单注/串场草稿；游戏统一承载页和供应商适配器。演示数据下提交按钮应保持模拟或禁用，直到合法真实服务、交易规则和结算系统明确。
4. **账户与记录**：整合用户中心、钱包、投注与游戏记录。需要后端接口、权限、日志与对账，不宜用浏览器本地存储冒充真实资金账本。
5. **供应商与运营内容**：仅接入有权限的游戏/流媒体服务，处理启动鉴权、可用性、失败回退、内容授权及版本/地区差异。彩票部分等待实际页面或规范后再细化。

## 与当前工作区的关系及待确认

当前工作区 `poly` 是名为 `marsket-demo` 的 React/Vite 项目，现有主导航是“预测、美股、游戏、排行榜”，并有用户、管理和钱包等进行中的改动。它与参考站的信息架构有明显差异，且工作区已有多处未提交修改。建议把参考站复刻做成独立应用或明确的独立模块，避免直接覆盖现有功能。实施前需确定目标是**视觉与交互演示**、**可连接供应商的前端**，还是**含真实资金和订单的完整平台**；三者的工程范围差异很大。

未验证：彩票主体、真实投注提交/确认/结算、充值提现、游戏内资金转移、移动端断点、所有供应商游戏可用性。当前调研不能推断这些流程的业务规则。
